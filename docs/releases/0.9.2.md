# recordbox 0.9.2

This release improves how a mapped controller follows the decks and makes STEMS preparation easier to use while playing. It includes the library, analysis and audio changes merged after v0.9.1. [Full comparison](https://github.com/fantuz/recordbox/compare/v0.9.1...v0.9.2)

## Playing with a MIDI controller

- Vinyl scratch now follows the distance the platter actually reports, including movement received just before release. Needle Lock uses the touch state at the instant the strip was pressed. Hardware tempo sliders remember their position across a reset, sync master change or tempo range change. The pickup arrows show how to regain control.
- The browse encoder follows visible tracks and folders, including filtered playlists. PLAY and CUE lamps distinguish a held preview, playback, pause and track end. A controller can regain its feedback port while its input and MIDI Learn session stay connected. Changing Learn rows or devices clears stale input from the previous selection.
- Run `recordbox --midi-ports` to list ports or `recordbox --midi-probe "port name" 10` to listen to one input. Linux and macOS also have a temporary virtual-controller command. The optional session trace can record input, routed actions and feedback. The two-deck DDJ-GRV6 software replay matched all 1,773 expected events and 12 feedback messages. Physical platter calibration and lamp behavior still need checks on the intended controller. [Controller guide and measurements](https://github.com/fantuz/recordbox/blob/v0.9.2/docs/UPSTREAM-INTEGRATION.md#midi-controllers-through-fcffc8d)

## STEMS, playback and hardware setup

- Both decks in EXPORT Dual Player can request and cancel STEMS independently. One full-track separation runs at a time. The deck shows whether a job is queued, reading audio, loading the model, separating or saving. Switching layouts or detaching the browser keeps a request alive while the track is on a deck.
- New profiles default to a **50 GB STEMS cache**. Existing cache budgets carry forward. New cache writes reserve 10% of the cache volume, including with **Keep all saved stems**. First launch of a new version or acceleration build checks the local hardware and recommends eligible analysis settings. Manual choices carry forward within the device’s safety limits. [Playback and hardware setup](https://github.com/fantuz/recordbox/blob/v0.9.2/docs/PLAYBACK-PERFORMANCE.md) · [Cache and backup behavior](https://github.com/fantuz/recordbox/blob/v0.9.2/docs/LIBRARY-SYNC.md#how-much-separation-is-saved)
- Multi-output interfaces now send Beat FX and the sampler through the selected stereo master pair even with headphones disabled. Delay processing, effect switching and waveform overlays do less work during playback. The audio-load tooltip reports callbacks that exceeded the buffer deadline. [FX and playback diagnostics](https://github.com/fantuz/recordbox/blob/v0.9.2/docs/PLAYBACK-PERFORMANCE.md#diagnosing-interruptions-when-enabling-effects)

## Preparing a library

- The optional installed beat-grid model corrects additional half- and double-tempo errors and irregular intervals. Where a regular tempo cannot describe the result, recordbox keeps the finite sequence of measured beats. Classic USB export and reimport preserve it when the DAT and EXT contain a verified matching grid. [Beat-grid changes and verification](https://github.com/fantuz/recordbox/blob/v0.9.2/docs/UPSTREAM-INTEGRATION.md#optional-beat-model-from-4b4756e)
- Related Tracks and Track Suggestion rank local matches and explain what makes them fit. Matching works offline. An optional recording-genre lookup sends artist and title for up to 100 selected tracks to MusicBrainz. It requires a OneTagger CLI build supporting `lookup --json`. The published OneTagger v2.3.0 predates that command. [Companion CLI change](https://github.com/fantuz/onetagger/pull/93)
- Desktop write-back offers a checked recovery-backup box on every preview and shows native paths in the result. Clearing it skips the retained backup for that operation. Grid edits still stage the data needed to recover an interrupted write. [Write-back and recovery](https://github.com/fantuz/recordbox/blob/v0.9.2/docs/LIBRARY-SYNC.md)

The dependency audit continues to track two existing advisories for the transitive quick-xml 0.30.0 package. [Advisory baseline](https://github.com/fantuz/recordbox/blob/v0.9.2/.github/security/advisory-baseline.json)
