# recordbox 0.9.3

Related Tracks and Track Suggestion can now use recording and release metadata from three catalogs. Local matching still works offline. [Changes since v0.9.2](https://github.com/fantuz/recordbox/compare/v0.9.2...v0.9.3)

## Looking up related track tags

- Select up to 100 tracks and choose **Look up related track tags…**. MusicBrainz is selected by default. Apple iTunes (US) can supply the song’s primary genre. Deezer can supply genres and a label from the album linked to an exact artist, title and edition match. Each source is optional.
- The installed OneTagger CLI receives the artist and full title. recordbox saves confirmed matches in its active catalog and leaves your audio files and embedded tags untouched. Existing MusicBrainz entries carry forward. The original MusicBrainz-only CLI command remains supported. Apple and Deezer need the provider selection introduced in OneTagger 2.4.0. [Companion CLI change for OneTagger 2.4.0](https://github.com/fantuz/onetagger/pull/93) · [OneTagger releases](https://github.com/fantuz/onetagger/releases)
- Right-click one track and choose **Related track metadata sources** to see its external entries. Track Suggestion counts overlapping genres once and gives your library label priority. The optional local analysis checkbox uses your current analysis settings.
- You can continue browsing while the catalog is busy, cancel a batch, or reopen the last result. The summary shows the outcome for each selected provider. If one provider fails, the other providers can finish. recordbox discards results for tracks whose artist or title changed during lookup.

## Ranking and packaging

- In a synthetic 40,000-track library, median warm Mix ranking with three saved sources fell from 219 ms to 194 ms over nine interleaved trials. Cold Mix ranking for a source with no waveform fell from 116 ms to 49 ms. The study includes its input generator, ranking checks and rerun commands. [Track Suggestion measurements](https://github.com/fantuz/recordbox/blob/v0.9.3/docs/studies/track-suggestion/README.md)
- Each package runner builds the shipping executable and its matching native test harness together. Windows still checks both STEMS models on the CPU and Microsoft’s WARP software driver, including multi-segment output parity and device release. The shipping archives have separate extraction and launch checks. [Build and packaging guide](https://github.com/fantuz/recordbox/blob/v0.9.3/docs/BUILD-AND-PACKAGING.md)

The dependency audit tracks two unresolved advisories for the transitive quick-xml 0.30.0 dependency, RUSTSEC-2026-0194 and RUSTSEC-2026-0195. [Advisory baseline](https://github.com/fantuz/recordbox/blob/v0.9.3/.github/security/advisory-baseline.json)
